# Changelog

All notable changes to this package are documented here. This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Rules for the author requirements WAI-ARIA 1.2 states in a role's or an attribute's text, not its tables, each a MUST, so each fails: a toolbar without a name on a page with several (`wai-aria-toolbar-names`), a combobox whose `aria-controls` names no listbox, tree, grid or dialog (`wai-aria-combobox-popup`), a spinbutton that owns more than a textbox and two buttons (`wai-aria-spinbutton-owned`), `aria-colindex` and `aria-rowindex` that don't grow along a table or exceed its `aria-colcount` and `aria-rowcount`, and counts below what the page shows (`wai-aria-table-indexes`), an `aria-setsize` below its set's items on the page or unlike its siblings' (`wai-aria-setsize`), and `aria-keyshortcuts` that misname a modifier key (`Ctrl` for `Control`) or put one after another key (`wai-aria-keyshortcuts`). `docs/COVERAGE.md`: 280 WAI-ARIA 1.2 cases, 257 fail, 22 are questions, none is missed.
- How a person answers each question names the case found, and says it in WAI-ARIA's words (`review.js`, core's `standard.review`): under `wai-aria-1.2`, a finding of `aria-haspopup="menu"` that controls a dialog reads "The popup has role dialog, not menu, which fails WAI-ARIA 1.2 aria-haspopup", where core's steps name WCAG 4.1.2. A scan that runs a WCAG profile too keeps core's. The pack's own rules' steps name what they found as well (the attributes on a `none` element, a caption's parent). Needs core 1.15, for placeholders in steps and `standard.review`.
- `proceduresFor` lists what is valid, from the Recommendation's role tables: the roles that need a name, the abstract and deprecated roles, each role's required, supported and prohibited states and properties, its required parents and children, and each attribute's value type and tokens, with the ranges, sets and table counts it must respect.

### Fixed

- `aria-valuemin` above `aria-valuemax` fails `attribute-values`, where it was a question: WAI-ARIA 1.2 says authors MUST keep `aria-valuemax` at least `aria-valuemin`.
- The procedures' steps no longer say `aria-roledescription` is prohibited on caption, code, paragraph and the like (only generic prohibits it), that a landmark needs a name when its role repeats (only region, form, and each of several toolbars do), or that a deprecated role fails `roles` (authors SHOULD NOT use one: a question).

- Rules of the pack's own for what no core rule checks: a scrollbar's `aria-controls` (`wai-aria-scrollbar-controls`) and a feed's articles (`wai-aria-feed-articles`, which counts what the feed owns as the accessibility tree does: its `aria-owns`, and HTML-AAM's implicit roles, looking through what is generic or none), which fail; a caption outside a figure or table (`wai-aria-caption-context`) and a state on a rendered `none` or `presentation` element (`wai-aria-presentational-attributes`), which are questions, as WAI-ARIA only recommends against them.
- Every name-from-author role WAI-ARIA requires a name for is checked: `wai-aria-role-name-present`, a variant of core's `aria-role-name-present` with its setting `roles: 'all'` (core 1.15), adds application, marquee, table, tabpanel and treegrid, and takes core's rule's place in the rule map. An empty heading (`empty-heading`) fails `name-required`, and an empty column or row header (`empty-table-header`) is a question there.
- A heading with no `aria-level`, or a combobox with no `aria-expanded`, is a question under required states, where it counted for nothing: WAI-ARIA's role tables give neither a default.
- WAI-ARIA 1.2 as a standard: the profile `wai-aria-1.2` runs core's ARIA rules and reports one result per author requirement (names required, roles, required states, supported and prohibited attributes, values, owned elements, context roles). Each rule's findings are read by WAI-ARIA's own wording, by reason code: a MUST or MUST NOT fails the requirement, though WCAG may only ask about it (an unnamed `role="grid"`); a SHOULD is a question. A requirement no rule fails is a question, never a pass, since the rules check what the markup states and not all the requirement covers. How a person checks each one by hand is in `proceduresFor`. Needs core 1.15, for `outcome: 'fail'` in a rule map.
